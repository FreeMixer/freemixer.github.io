    Function finiteNumberWithinOf

    • finiteNumberWithinOf(limit: ControlLimit): FieldCodec<number>

      A finite number REFUSED outside a declared travel — the codec a SETTING uses where finiteNumberOf is the codec a GESTURE uses.

      The distinction is the one intWithin already draws, applied to a continuous quantity. A fader dragged past its end should CLAMP: the gesture is continuous, the operator watches the knob stop, and the desk answering "that far and no further" is the whole feedback. A value TYPED INTO A POLICY is a statement about how the desk will behave later, and clamping it hides that the desk will now come up somewhere the operator never asked for. Nothing shows it, because nothing is moving at the time.

      It refuses off the STEP grid for the same reason, and intWithin's reason for refusing a fraction: a travel that resolves in 1 dB steps cannot hold 0.5, so storing it is storing a value the thing behind the control rounds away — and downstream, a come-up default that is not representable is published as ABSENT, so a silently-quantized setting reads as no setting at all. OUT_OF_RANGE carries min, max and step, which is the whole legal set.
