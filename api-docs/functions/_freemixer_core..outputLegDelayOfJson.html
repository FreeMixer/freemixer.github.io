      A PERSISTED destination's per-side delay, migrating the legacy whole-destination delayMs.

      WHY THIS EXISTS AND WHERE IT DOES NOT APPLY. The leg ROW's break is total: a PATCH naming delayMs is refused UNKNOWN_FIELD, because a client writing it would be writing a control whose caption is wider than its write. A SAVED SHOW is the opposite case — it is a document the operator made, it was valid yesterday, and refusing it would boot the desk with MAIN unpatched. The live autosave carries routeTo: {L, R, trimDb, mute, delayMs} today. So the persisted form MIGRATES and the door REFUSES, and this is the one function that says what the migration is.

      L AND R, NEVER C. One shared delay_ms was applied to busL and busR and to nothing else — main_C had no delay stage at all until this ruling gave it one. Fanning the legacy figure onto C as well would make an lcr main play a delay it never played, which is a change of audio smuggled in as a migration. The centre restores un-delayed, exactly as it was.

      A per-side key already present WINS: a document written by this build says what it means, and a stale delayMs beside it is not an instruction to overwrite it.
