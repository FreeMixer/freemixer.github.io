      The facts a CHANNEL CONFIG's declared-absence pass clears (spec revision 3, #665) — every onAbsent: 'clear' fact ALL of whose snapshot fields the config carries.

      A config is a whole-channel statement about a NARROWER channel than a session's: it says what this channel's processing IS, and nothing about where it is patched, how loud it sits in the mix, or what it is called. So the pass is the session's, run over the config's own field set. Running the session's set would zero a fader no config ever claimed to speak for; running nothing — what it did until now — leaks config A's gate onto a channel loading config B.

      Exported because its one consumer besides the apply is the battery that PROVES it, and a hand-kept list in the test would be the same defect one file further out.
