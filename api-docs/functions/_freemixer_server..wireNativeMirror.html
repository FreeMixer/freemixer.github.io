      Wire the installed DSP mirror into the server and the mixer — the ONE sequence every composition root runs once the mirror exists (startConsole and the job desk), answering the sink a committed /chain order write reaches the lane's stage walk through.

      • The mirror is wired and its boot assert has driven the whole console onto the native lanes: the server is told, because from here a projection that finds no mirror is a control that does not reach audio — before here it was only the boot sequence.
      • An ORDER write reaches the walk through the same push. One path to audio: the order row's station calls this and nothing else, and what it moves is measured by reading the LANE back, never by the row that wrote it (southbound actuator contract §6c).
      • THE IN-LANE INSERT DETOUR, injected the way every native seam is (native-pipewire-engine: the root hands the ONE native client to the engine). Without it a racked plugin still reaches the audio — ahead of the whole lane — and the placement is REFUSED rather than silently claimed.
      • THE IN-PROCESS CLAP BANK (CLAP hosting spec §11 5e): the server learns the node's linked list and the mixer binds where the server's one hosting derivation says a CLAP runs in-process; a node without the bank injects nothing, and no CLAP has a body.
      • The RESTORE assert: every session load / scene recall re-drives the whole console's built-in DSP onto the lanes, so a lane can never outlive the show that set it (rig 2026-08-05 — see BuiltinDspMirror.assertAll). The root owns the native node, the server owns when a restore has landed.
