    Interface ChannelConfigProcessing

    One channel's processing captured for reuse: its plugin chain (ordered plugins + params + presets) + channel processing (gain/trim/pan/phantom/pad/SENS/polarity). Stored channel-agnostic so it can be applied to any channel. Borrows MOD-UI's preset round-trip (enumerate / default / mark-current / save user bundle).

    Same digitalGainDb/headAmpGainDb split as ChannelSnapshotJson — a retired gainDb or sensDbu here is exactly as ambiguous as on a whole session and gets the same loud, never-reinterpreted treatment at apply time.

    Optional ReadonlyalignDelayMs

    alignDelayMs?: number

    INPUT ALIGNMENT delay, ms — the input-stage latency that pushes this microphone back to meet another on the same source. Persisted because a show that restores without it comes back COMBING: the operator aligned two mics, the desk forgot, and nothing says so.

    Optional ReadonlyalignReference

    alignReference?: string

    WHICH channel this one was aligned against — the record the next operator needs to check or redo the alignment. No audio consequence of its own.

    Optional ReadonlydigitalGainDb
