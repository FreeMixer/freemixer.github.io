    Interface OutputRouteState

    One output destination in a PatchbayOutputStateMessage: its role-keyed sink legs (L / R, at least one) + the per-destination trim (issue #158) + delay (issue #183). Fields absent ⇒ unity / un-muted / no delay. A stereo route carries both L and R; a mono-leg route only its own role, so the crosspoint lights the exact routed port per leg (#183).

    deferred?: boolean

    Whether this route is deferred/absent (issue #154): the destination sink is not in the live graph (unplugged interface, a stopped node), so the route carries no audio yet. Surfaces ghost the cell instead of showing it identical to a live route. Sourced from the #168 deferral ledger; absent (never false) for a live route.

    Optional ReadonlydelayMs

    delayMs?: number

    Per-destination DELAY (ms) applied AFTER the trim/fold — the time-alignment control.

    Optional Readonlyfold

    fold?: true

    Whether this destination is a mono FOLD (#284): every present leg lands on the ONE sink port (L === R), so the engine sums busL+busR into it through a single OMX_ROUTE_FOLD route at the design's fixed MONO_FOLD_COEF (exactly ½) — a correlated L≈R signal lands at unity, and there is no per-destination figure to carry (ruling 2026-09-07).

    Derived from the legs (a client could compute L === R), but sent EXPLICITLY so a surface cannot render a fold as if it were two ordinary legs: the two look identical in the crosspoint (both cells lit at that port) yet behave completely differently — a fold is ONE destination with ONE trim and a fold gain, and un-ticking either cell leaves the other a plain leg. The console must never quietly do something other than what it shows. Absent (never false) for an ordinary leg / stereo route.
