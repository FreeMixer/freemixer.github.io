    Interface RtLoadState

    The engine's RT load on the wire (task #121): the measured busy-per-quantum reading (see core RtLoadReading — ratios of the real cycle budget) plus the headroom verdict's honest operator copy. level/message come from core assessRtHeadroom over the same reading the server gated with, so the UI never re-derives (and never disagrees with) the add-band guard's decision.

    interface RtLoadState {

    Cycles in which the graph driver's accumulated xrun duration GREW — the driver xrun events the engine's own RT callback witnessed. An engine that joined a graph already losing time does not inherit that history: its first cycle read is a baseline.

    Inherited from RtLoadReading.driverXruns

    ReadonlyidlePolicy

    idlePolicy: IdlePolicyFacts | null

    The idle policy as the ENGINE holds it (2026-10-16-engine-idle-policy.md §6): the target, the request its fd holds, the box's aggregate read back, the state's code and a refusal's errno. Read-only, served as-is; null while the engine has published none.

    Readonlylevel

    Readonlyoverruns

    overruns: number

    Cumulative count of cycles whose busy time reached the whole COMPUTE budget — the engine's own missed deadline. It says nothing about a cycle the DRIVER could not deliver; that is driverXruns.

    Readonlyworkers

    workers: number | null

    The RT thread split as the ENGINE runs it (2026-09-27-rt-thread-split.md §7 lane 1 item 2), read-only and derived from its published fact block, never re-derived: workers (driver included; 1 is the single walk), perWorkerBusy (each worker's busy EMA on the busyEma gauge, driver first) and partitionRatio (the prediction the partitioner used at that N). null / [] while the engine has published no split facts.
