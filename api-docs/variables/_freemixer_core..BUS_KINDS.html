    BUS_KINDS: Readonly<Record<ChannelKind, boolean>> = ...

    The audio-bus channel kinds: the kinds whose channels CARRY and SUM audio — a signal is routed into them and read back out. This is the single, honest source of truth for "is this an audio bus?" (see isBusKind). Never re-derive it as a local Set(['main','aux','mix','matrix']): such a copy silently omits fxReturn and mixMinus, and "bus-ness" then disagrees across layers.

    The partition — WHY each kind is in or out:

    • main, mix (sub-groups), aux (monitor/FX sends), matrix, mixMinus (N−1), fxReturn (send/return input bus) — IN. Each is a summing node: inputs feed it, it carries audio, it has a strip/master. fxReturn was wrongly excluded by the old Sets even though it sums the return legs; it is a genuine audio bus and now classifies as one.
    • fxSend — IN. It is an aux-like send point: a summing bus that feeds an FX unit. It carries audio exactly like an aux, so it belongs with the buses (the old Sets omitted it too).
    • input — OUT. It is a channel (a source strip), not a bus; it feeds buses.
    • dca, muteGroup — OUT. Control-domain groups. They couple fader/mute across members but carry NO audio of their own (nothing is summed into a DCA), so they are not buses.
    • cue — OUT. The solo/monitor (PFL/AFL) bus is a monitor path, not part of the program-audio summing topology the bus helpers gate on; it is handled by the dedicated monitor path, so it is deliberately excluded here (matching the pre-existing behaviour — neither old Set listed cue).
