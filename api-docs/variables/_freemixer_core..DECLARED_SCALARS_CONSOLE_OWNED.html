    DECLARED_SCALARS_CONSOLE_OWNED: Readonly<Record<string, ConsoleOwned>> = ...

    The macros the scalar door renders from the console's OWN numbers (openmixer#2134 audit rows 1 and 3). They are the console's behaviour, so omx_console_limits.h is their owner header and the render is no copy of a library definition. A key is either a PREFIX with a trailing _ (a group several core exports render under: ROOM_MODE_) or an EXPORT NAME (that macro and its leaves: TRUE_PEAK_OVER_DB, FBS_HOLD_SECONDS_RANGE_*). The test holds each key to that: at least one macro renders under it (the entry is not stale); every one of them comes from a core export or from a declaration the declarations package itself declares (@freemixer/declarations/console-only), never one bound from the contract; and no installed omx-dsp header publishes a macro under it. A library that takes a group over turns the entry red, and the group moves to DECLARED_SCALARS_OWNED_BY_HEADER with the console render dropped.

    Row 1 (operator 2026-10-24, console-owned by design): the kernels do not read these numbers, the console's policy does, and the contract carries only what more than one consumer reads.
