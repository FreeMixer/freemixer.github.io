Benchmarks

The same plugins on four hosts

Each scenario runs the same plugins at the same sample rate and buffer size on each host. The load is the DSP load of the JACK server that drives them, read while the scenario plays. Levels, where this page gives them, are measured digitally at JACK ports.

The bench harness in the plugin-hostd repository writes the runs on this page and repeats them on any machine. Read the README.

omx-clap-host, one process
The CLAP host driven directly through the mod-host protocol on its own port. All plugins share its one process.
plugin-hostd
The plugin daemon with omx-clap-host as its worker. Plugins run in isolated workers, and a chain is one worker.
mod-host
mod-host, the host behind MOD-UI and Zynthian's effect chains. LV2 plugins only; the version is in the footer.
jalv
One jalv process per plugin, the way plugins ran on a Zynthian before.

Lowest buffer

Lowest buffer without an xrun

A buffer is the short block of audio a host processes at a time, counted in frames. The host must finish each block before the next one is due; if it does not, the sound glitches, and that glitch is an xrun. The smaller the buffer, the less time audio waits before it comes out, so a smaller buffer is a lower latency. How it was measured

Raspberry Pi 5 Model B Rev 1.0, governor performance, JACK on the alsa driver of the audio interface hw:Pro73107815, real-time priority 70, 3 periods per buffer, at 48 kHz, 96 kHz; each row names its rate and frames. Every figure is the median of 3 repeats, with the lowest and the highest repeat beside it. Nothing is rounded; a figure is shown as the harness wrote it. Everything is measured digitally, at the JACK server and its ports.
