Benchmarks

The same plugins on three hosts

Each scenario runs the same plugins at the same sample rate and buffer size on each host. The load is the DSP load of the JACK server that drives them, read while the scenario plays. Levels, where this page gives them, are measured digitally at JACK ports.

The bench harness in the plugin-hostd repository writes the runs on this page and repeats them on any machine. Read the README.

omx-clap-host, one process
The CLAP host driven directly through the mod-host protocol on its own port. All plugins share its one process.
plugin-hostd
The plugin daemon with omx-clap-host as its worker. Plugins run in isolated workers, and a chain is one worker.
mod-host
The mod-host program as Zynthian ships it. LV2 plugins only.

How it was measured

Raspberry Pi 5 Model B Rev 1.0, governor performance, a private JACK server on the dummy driver at 48 kHz, 256 frames. Every figure is the median of 3 repeats, with the lowest and the highest repeat beside it. Nothing is rounded; a figure is shown as the harness wrote it.

Rows marked omx-clap-core ran on the version named in the row. The omx-clap-host rows ran on omx-clap-core 0.26.3 and the plugin-hostd rows on 0.26.4, because on 0.26.3 the plugin-hostd chains did not form (see the rows that did not pass).

On omx-clap-core 0.26.3 none of the plugin-hostd chains formed: Calf and the DPF plugins set the flush-to-zero bit of the FPCR register when their library is opened, and the register guard took it for theirs and moved each such plugin to a worker of its own. 0.26.4 logs that change and no longer isolates the plugin for it.

One worker per plugin is the heavy mode: 24 processes and 24 JACK clients on four cores. It is not the default.
