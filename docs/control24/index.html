Connecting a Digidesign Control|24.

The Control|24 and the ProControl talk to their host over Ethernet, in a protocol of their own called DigiNet. libdiginet is a library that speaks it. This page says what the desk needs from the network and how to install the library and its test tool.

01

What DigiNet is on the wire.

DigiNet is not IP. Every frame is a raw Ethernet II frame with EtherType 0x885F: no IP address, no DHCP, no port number. The desk is known by its MAC address, which starts with Digidesign's prefix 00:a0:7e.

An idle desk broadcasts an announce to ff:ff:ff:ff:ff:ff about every 7 seconds, with its name (CNTRL|24 on a Control|24) and its firmware version. A host answers it, and from then on every frame is unicast between the desk's MAC and the host's MAC: faders, keys, lamps, displays, meters, and the acknowledgements and keepalives that hold the session up.

The 7-second interval and a port at 10 Mbit/s half duplex were measured on a ProControl, the Control|24's sibling of the same generation. A modern network card cabled straight to the desk may not settle on that link mode, and a cheap unmanaged 10/100 switch between the two does.

02

It can share a network with the web UI.

A switch forwards a DigiNet frame like any other Ethernet frame, so the desk can sit on the same segment as the tablets and laptops that open the web UI. Machines that speak only IP ignore an EtherType they do not know. Apart from the desk's broadcast announce, a switch delivers DigiNet frames only to the console host's port, because they are addressed to its MAC.

The frames are small: libdiginet puts at most 48 commands and 314 bytes in one, and paces display writes 2 ms apart.

03

What the network needs.

  • The same layer-2 segment, with no router in between.

    DigiNet has no IP header, so a router has nothing to route. The desk and the console host must be on the same Ethernet segment: one cable, or switches only.

  • The untagged (native) VLAN of the host's port.

    The desk sends plain frames with no VLAN tag. Put it on the untagged VLAN of the switch port the host is on, and use the host's plain interface, not a VLAN sub-interface.

  • A cable from the desk to the host.

    Some Wi-Fi bridges and range extenders forward only IP and ARP and drop an EtherType they do not know. Keep the path from the desk to the host wired. Web UI clients on Wi-Fi are fine: they talk IP to the console.

  • Not on the REAC stagebox link.

    The interface that carries the REAC stageboxes carries their audio and nothing else. The desk goes on another interface of the host.

04

Security.

DigiNet has no authentication. The desk takes a session with whichever host answers its announce, with no password and no key, and nothing in a frame proves who sent it.

On a network you control, that is enough. On a venue LAN shared with other people, give the desk and the console host a segment of their own: a separate switch, or a VLAN that only the two of them are on.

The desk also accepts a family of system messages (F0 13 xx 70 …) that writes to its own memory. libdiginet refuses to send it.

05

Install.

libdiginet 0.1.0 is in the FreeMixer package repositories: RPMs for Fedora (x86_64, aarch64) and DEBs for Debian bookworm and trixie (amd64, arm64). Add the repository as on the other pages and install diginet-tools, which brings the library with it.

sudo dnf install https://www.openmixer.org/rpm/openmixer-release.noarch.rpm
sudo dnf install diginet-tools

libdiginet · libdiginet0 · libdiginet-transport0

The protocol library and its transport: discovery, the session handshake, acknowledgements, keepalive and retransmit.

diginet-tools

diginet-probe, the command-line tool for testing a desk.

libdiginet-devel · libdiginet-dev

Headers, pkg-config files and the protocol grammar, for building a program on the library.

diginet-probe opens a packet socket, and that needs one capability, cap_net_raw. The package sets it on /usr/bin/diginet-probe when it installs, so the probe runs as your own user, not as root. A copy you build yourself has no capability until you run setcap cap_net_raw=ep on it, and again after every rebuild.

With the desk cabled and powered on, the first look sends nothing: it only listens for the announce. The probe then wakes the desk, moves fader 1, lights a lamp, writes a scribble strip, logs every key and touch, and ends with a summary.

# listen only: the desk's announce, about every 7 seconds
sudo tcpdump -i <if> -e 'ether proto 0x885f'

# wake the desk and run the first test
diginet-probe -i <if>

Every option and exit status of the probe: docs/probe.md. The protocol as it is known, with a source for every claim: docs/protocol.md.
