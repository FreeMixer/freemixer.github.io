Plugin catalog

What we measured about each plugin.

Every plugin is loaded, run and measured on a real device before OpenMixer offers it: the audio callback is watched for allocations, locks and system calls, and CPU cost and latency are measured. These are the records of 2016 plugins on 2 platforms, grouped by what each platform could accept.

Reading the verdicts

How a verdict is reached.

Accepted
Passed every measurement on this platform and is offered for use.
Accepted with conditions
Works, but only in a process of its own. The reason shown is why it is not offered without that condition.
Refused
Not offered on this platform. The reason shown is why.

A plugin is tested once for each way it can be offered. It is accepted when one of those ways passes every measurement, accepted with conditions when the best it can do is to run in a process of its own, and refused when it can be offered in no way.

The long-run stability test was not part of these records, so no plugin was judged on it either way.

The data

Where these figures come from.

Every figure on this page is read from the qualification records, which are public. The records are pinned to one version, and a script regenerates the page's data from it and checks that nothing differs.

  • The data format and how to refresh it

A result holds for the file and version shown on the row. If you maintain a plugin and a row is wrong or out of date, each open row links to a form to report it.
